# Milestone 120 — Explicit resumable restoration backend and CLI

The user authorized all following work that does not require visual review. Completed 120-frame segments can now be recorded in a persistent opt-in job folder, retained after cancellation/failure or a process force quit, and reused by a fresh process. The default path continues to use a disposable workspace.

A session holds a nonblocking exclusive kernel file lock for the complete pipeline run. Lock ownership ends automatically on process termination. Resume verifies the full source SHA-256, canonical source/output paths, settings, the actual selected model package files, bundled FFmpeg content, and the explicit frame-processing contract version. Developers must bump that version when processing behavior changes. Every recorded segment is rehashed before reuse; its original production validation is preserved by its content digest. Unrecorded segments and interrupted frame/join/audio work are rebuilt. Cleanup is restricted to recognized job files after validation; unknown files and links are refused before cleanup. Existing output and destination partial files remain protected.

The chunk coordinator skips only a contiguous recorded prefix and records each newly validated durable segment before advancing. An interruption during the current block repeats that block rather than claiming it is complete. Completed video blocks can all be reused when interruption occurred during final assembly/audio. Successful promotion removes the saved workspace. Preparation and cancellation now have an explicit one-run pipeline boundary; refusing an existing ordinary workspace never deletes its contents.

CLI: `--restore lightweight --checkpoint-dir PATH` creates a new saved job. PATH must begin with `SwiftyTranscoder-Restoration-`, with an existing parent folder. Repeat the identical command with `--resume` after interruption. `--resume --dry-run` rehashes and verifies the saved source/settings/model/segments without writing. Choose a permanent folder for persistence across reboot. Concurrent resume and fresh reuse of an existing folder are refused. Saved folder paths are reported on interruption/failure. Ordinary conversion behavior remains unchanged.

Validation evidence is in `.build/milestone120-evidence/` and `.build/milestone121-evidence/`. The complete suite passed 165 tests in 40 suites; 29 focused tests passed after the final lifecycle changes. Real short HD tests exercise Ctrl-C, SIGKILL, concurrent refusal, changed settings, new-job conflict, dry-run nonmutation, complete 240-frame HEVC output at 1920×1080, AC-3/AAC audio, saved-block hash/mtime preservation, output promotion/cleanup, and source preservation. Final real-test results and the GUI workflow are recorded in Milestone 121. No user playback acceptance is claimed here.
